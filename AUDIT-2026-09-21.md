**Shift lock (KASSA) was CLOSED** — 0 active shifts live (82 historical).
When shift is closed, `requireActiveShift()` (src/lib/shiftLock.ts) returns 403
on **7 routes**:

| Route | User-visible effect |
|---|---|
| /api/orders/clear-table | Masa boşaltıla bilmir → **stuck "occupied" tables** |
| /api/orders/bill-request | "Hesabı bağla" request blocked |
| /api/orders/reopen | Paid order reopen blocked |

| /api/reservations/walk-in | Rezervasiya walk-in blocked |
| /api/kitchen/void-comp-waste | KDS void/waste blocked |
| /api/orders/delivery-status | Delivery status change blocked |

**Design flaw:** the 403 message says "Smena bağlıdır. **Mütəşəddim icazəsi ilə
əməliyyat edə bilərsiniz**" — but NO route accepts a manager override
(`requireActiveShift()` is called with no args everywhere; no PIN-verified path).
Inconsistency: **payment works with closed shift, clearing the table after
payment does not** → operator pays, table stuck, looks like a data bug.

Evidence: table_floors row 996 = `occupied, guest_count=0, current_order_id=NULL,
reservation_id=NULL, order_ids={}` — all clear_table_atomic guards pass; the
403 came before the RPC.

**Unblock (now):** open KASSA (start shift) → MASANI BOŞALT works.
**Fix candidates (QF9?):** (a) manager-PIN override wired end-to-end, or
(b) clear-table exempt from shift lock (it deletes no money), or (c) UI: when
403 shift-lock, open the KASSA modal inline instead of a dead-end toast.
